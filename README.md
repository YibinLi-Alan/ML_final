# 💳 Credit Card Customer Churn Prediction

An end-to-end machine learning system that predicts credit card customer churn for retail banking. A Random Forest classifier wrapped in a Streamlit web interface and deployed on AWS (S3 + EC2).

Built as a proof-of-concept capstone project covering the full lifecycle — data acquisition, EDA, model training, evaluation, cloud deployment, and a working user interface.

## What This Project Is

Credit card customer attrition is expensive — acquiring a new customer costs roughly **5×** more than retaining an existing one, and a 5% improvement in retention can lift profit by up to **85%**. Most banks only find out a customer is leaving after the account has been closed.

This project flags at-risk cardholders **before** they cancel, so a retention analyst can intervene with a phone call, fee waiver, or targeted offer.

**End user:** A bank retention analyst (not an engineer, not a data scientist).

**What the system does:**
1. Loads a pre-trained Random Forest model and its preprocessing artifacts
2. Presents a three-column form for the analyst to enter a customer's profile
3. Returns a churn probability, a color-coded risk tier (Low / Medium / High), and a plain-English action recommendation — all in under 1 second

## Results

Random Forest beat the alternative (a 3-layer MLP) on every metric on the held-out test set of 507 customers:

| Metric | MLP | Random Forest | Δ |
|---|---|---|---|
| Recall *(primary)* | 0.784 | **0.865** | +0.081 |
| Precision | 0.716 | **0.865** | +0.149 |
| F1 Score | 0.748 | **0.865** | +0.117 |
| ROC-AUC | 0.963 | **0.989** | +0.026 |
| Accuracy | 0.923 | **0.961** | +0.038 |

**Recall** is the headline metric — missing a churner means losing the account forever, while a false alarm just costs an unnecessary phone call. The 8-point Recall improvement translates to catching about 8 more at-risk customers out of every 100 before they close their cards.

## Environment Setup

### Prerequisites
- Python 3.10 or higher
- `pip` (or `conda`)

### Install dependencies

```bash
# Clone the repo
git clone <your-repo-url>
cd <your-repo-name>

# Create a virtual environment (recommended)
python3 -m venv venv
source venv/bin/activate          # macOS / Linux
# venv\Scripts\activate            # Windows

# Install everything from requirements.txt
pip install --upgrade pip
pip install -r requirements.txt
```

That's it for the environment. All Python dependencies — scikit-learn, pandas, Streamlit, imbalanced-learn (SMOTE), Jupyter, matplotlib, seaborn — are pinned in `requirements.txt` to the exact versions used during development.

> **Important:** scikit-learn must match between training and inference. If you train the model on one version and try to load the `.pkl` files with a different version, you will see warnings or errors. The pinned `scikit-learn==1.7.2` in `requirements.txt` is what the deployed system uses.

## Re-running the Pipeline

The pipeline has two stages: training (the notebook) and serving (the app).

### Stage 1 — Train the model (run the notebook)

```bash
jupyter notebook memo1.ipynb
```

Run all cells top to bottom. The notebook:

1. Loads `BankChurners.csv`
2. Drops the two leaky Naive Bayes columns and the customer ID
3. Performs EDA (univariate + bivariate plots, correlation heatmap)
4. Encodes categorical features with `pd.get_dummies(drop_first=True)`
5. Splits data 80% / 15% / 5% (train / val / test, stratified)
6. Applies SMOTE to the **training set only** (validation and test keep the natural 16% churn rate)
7. Standardizes numeric features with `StandardScaler` fit on the resampled training set
8. Trains a 3-layer MLP (64 → 32 → 16, ReLU, Adam, early stopping)
9. Trains a Random Forest (300 trees, `random_state=1`)
10. Evaluates both on train / val / test sets and prints a comparison table
11. Saves three artifacts to the working directory:
    - `rf_model.pkl` — the trained Random Forest (~34 MB)
    - `scaler.pkl` — the `StandardScaler` instance fit during training
    - `feature_columns.pkl` — the column order after one-hot encoding

> **Why three files?** Inference must reuse the *same* preprocessing as training. The scaler must be fit on training data (not refit per request), and the column order must match what the model was trained on. Saving them separately makes this explicit and lets us version them independently.

**Reproducibility:** With `random_state=1` everywhere and the same `BankChurners.csv`, the test-set metrics in the [Results](#results) table reproduce to within ±0.005. SMOTE introduces a small amount of nondeterminism even with a fixed seed.

### Stage 2 — Run the app locally

After the notebook has produced the three `.pkl` files in the working directory:

```bash
streamlit run app.py
```

Streamlit opens `http://localhost:8501` automatically. You should see the Customer Profile form. Fill in a customer profile, click **Predict Churn Risk**, and you should see a probability, a colored risk tier, and a recommendation in under a second.

If you want the app to be reachable from other devices on your network, run:

```bash
streamlit run app.py --server.address 0.0.0.0 --server.port 8501
```

## AWS Deployment Runbook

Step-by-step instructions to take this project from a clean machine to a live, publicly accessible Streamlit app on AWS.

**Target environment:** AWS Academy Learner Lab (also works with a regular AWS account — IAM role names will differ).

**Expected time:** 60–90 minutes the first time.

### Architecture

```
                                ┌──────────────────────────────────────────┐
                                │  AWS Academy · us-east-1                 │
                                │                                          │
   Browser                      │   ┌──────────────┐    ┌──────────────┐   │
   (analyst)  ──── HTTP :8501 ──┼─► │  EC2 t3.small│ ◄──│   S3 Bucket  │   │
                                │   │  Ubuntu 22.04│    │   3 .pkl     │   │
                                │   │  Streamlit   │    │   artifacts  │   │
                                │   │  tmux daemon │    └──────────────┘   │
                                │   └──────────────┘                       │
                                │            ▲                             │
                                │            │ IAM (LabInstanceProfile)    │
                                │            │ + Security Group (8501, 22) │
                                └──────────────────────────────────────────┘
```

Three services, deliberately simple for a POC:

- **S3** — durable storage for the three model artifacts
- **EC2 (t3.small)** — runs the Streamlit app, pulls artifacts from S3 on boot via the AWS CLI
- **IAM + Security Group** — `LabInstanceProfile` lets EC2 read S3 without hardcoded keys; Security Group opens port 8501 publicly and limits SSH to the team's IPs

**Why not SageMaker?** The model was already trained locally — there was no need to ship a 34 MB pickle up to a managed training service just to send it back down. EC2 + S3 + Streamlit is the right size for a single-user POC and keeps cost and complexity low.

### Prerequisites

- The three `.pkl` artifacts on your laptop (produced by running `memo1.ipynb`)
- An AWS Academy account (or a regular AWS account with EC2/S3/IAM permissions)
- A terminal

### Stage 1 — Start the AWS Lab

1. Log into AWS Academy → your course → **Modules → Learner Lab → Start Lab**.
2. Wait for the indicator to turn green (1–3 minutes).
3. Click the **AWS** button to open the Console.
4. Confirm the region is **N. Virginia / us-east-1** (top-right). AWS Academy only permits this region.

> Lab sessions expire every 4 hours. EC2 stops automatically; S3 data persists. Public IPs change after each restart.

### Stage 2 — Create an S3 Bucket and Upload the Model

1. Console search **S3** → **Create bucket**.
2. **Bucket name:** globally unique, lowercase — e.g. `churn-poc-<initials>-<digits>`.
3. **Region:** `us-east-1`. Leave all other settings at default (Block Public Access stays ON).
4. Click into the new bucket → **Upload → Add files** → select the three `.pkl` files → **Upload**.
5. Record the bucket name.

### Stage 3 — Launch an EC2 Instance

1. Console search **EC2** → **Instances → Launch instances**.
2. **Name:** `churn-streamlit-server`
3. **AMI:** Ubuntu Server 22.04 LTS, 64-bit (x86)
4. **Instance type:** `t3.small` (2 GB RAM — `t2.micro` will OOM)
5. **Key pair:** click **Create new key pair** → name `churn-key`, RSA, **`.pem` format**. Browser downloads `churn-key.pem`. **Save it somewhere permanent** — you cannot re-download.
6. **Network settings → Edit → Create security group** named `churn-sg` with two inbound rules:
   - Type `SSH`, Source `My IP`
   - Type `Custom TCP`, Port `8501`, Source `Anywhere (0.0.0.0/0)`
7. **Storage:** 8–20 GiB `gp3`
8. Click **Launch instance**. Wait until status is `Running` with `2/2 checks passed`.
9. Copy the **Public IPv4 address**.

### Stage 4 — Attach an IAM Role to EC2

Without this step, EC2 cannot authenticate to S3.

1. Select your instance → **Actions → Security → Modify IAM role**.
2. Choose **`LabInstanceProfile`** (AWS Academy) or any role with S3 read permissions.
3. Click **Update IAM role**.

### Stage 5 — Connect via SSH

```bash
# Set permissions on the key (once)
chmod 400 /path/to/churn-key.pem

# Connect (replace <EC2_PUBLIC_IP> with the actual IP)
ssh -i /path/to/churn-key.pem ubuntu@<EC2_PUBLIC_IP>
```

When prompted "Are you sure you want to continue connecting?", type `yes`.

**Common errors:**

| Error | Fix |
|---|---|
| `Permission denied (publickey)` | `chmod 400` the `.pem` file |
| `Connection timed out` | Your laptop's IP changed — re-edit the SSH rule in `churn-sg` and set Source to **My IP** again |
| `Host key verification failed` (after restart) | `ssh-keygen -R <EC2_PUBLIC_IP>`, reconnect |

### Stage 6 — Install the Application on EC2

All commands below run on the EC2 instance.

```bash
# 1. System packages
sudo apt update -y
sudo apt install -y python3-pip python3-venv unzip tmux

# 2. AWS CLI v2
curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o "awscliv2.zip"
unzip -q awscliv2.zip
sudo ./aws/install
aws --version

# 3. Python virtual environment
python3 -m venv ~/venv
source ~/venv/bin/activate
pip install --upgrade pip
pip install streamlit==1.56.0 scikit-learn==1.7.2 pandas numpy joblib imbalanced-learn

# 4. Pull artifacts from S3 (replace <YOUR_BUCKET>)
mkdir -p ~/app && cd ~/app
aws s3 cp s3://<YOUR_BUCKET>/rf_model.pkl .
aws s3 cp s3://<YOUR_BUCKET>/scaler.pkl .
aws s3 cp s3://<YOUR_BUCKET>/feature_columns.pkl .
ls -lh *.pkl
```

### Stage 7 — Copy `app.py` to the Server

From a **new terminal on your laptop** (not the SSH session):

```bash
scp -i /path/to/churn-key.pem app.py ubuntu@<EC2_PUBLIC_IP>:~/app/app.py
```

### Stage 8 — Run the App in tmux

Back on the EC2 instance:

```bash
tmux new -s streamlit
source ~/venv/bin/activate
cd ~/app
streamlit run app.py --server.port 8501 --server.address 0.0.0.0
```

Press Enter to skip the email prompt. You should see the External URL printed.

**Detach from tmux** (leaving the app running) by pressing:
1. `Ctrl + B`, release
2. `D`

You can now `exit` the SSH session — the app stays up.

### Stage 9 — Verify

Open in any browser, on any device:

```
http://<EC2_PUBLIC_IP>:8501
```

Fill in a customer profile, click **Predict Churn Risk**, and confirm the response.

### Resuming on a New Day

AWS Academy stops your instance after 4 hours. To resume:

1. **Start Lab** in AWS Academy.
2. EC2 → select the instance → **Actions → Start instance**.
3. **Note the new Public IP** (it changes on every restart).
4. SSH back in and reattach: `tmux attach -t streamlit`.
   If the session is gone, recreate it as in Stage 8.

### No Secrets in This Repo

Authentication on EC2 is handled entirely via the **`LabInstanceProfile` IAM role** — no access keys are stored on disk or in the codebase. The `.pem` private key for SSH never enters the repo.

If you fork this project for your own AWS account, do not commit:
- `*.pem` files
- AWS access keys (anything starting with `AKIA`)
- A populated `.env` file

## Notes & Limitations

- This is a proof-of-concept, not a production system. No authentication, no audit logging, no batch scoring.
- The deployed EC2 endpoint is short-lived — running in AWS Academy, which expires lab sessions every 4 hours and reassigns public IPs on restart.
- Retraining is manual. A production version would schedule retraining (e.g. via AWS Lambda or a cron job) to keep up with shifting customer behavior.
- The 0.4 / 0.7 risk-tier thresholds in the UI are business-driven, not model-driven. The model's classification threshold remains 0.5.
